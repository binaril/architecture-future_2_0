## 3. Обоснование разделения на домены

### Граница домена Клиники

Медицинские данные требуют жёсткой изоляции по требованиям 152-ФЗ и внутренней политике компании. Домен полностью закрыт: в платформу данных и витрину уходят только агрегированные события без персональных данных. ИИ-сервисы получают доступ к DS1 в режиме read-only исключительно через анонимизирующий слой.

### Граница домена ИИ-Сервисы

ИИ-модели имеют собственный жизненный цикл (обучение, версионирование, деплой), не связанный с клиническими операциями. Отдельный домен позволяет обновлять модели без риска повлиять на работу операторов в клиниках. Телеметрия медоборудования поступает напрямую в этот домен, минуя общий DWH.

### Граница домена Финтех

Финтех владеет банковской лицензией, что накладывает регуляторные требования (ЦБ РФ), несовместимые с совместным хранилищем. Бизнес-логика (расчёт кредитного рейтинга, антифрод) живёт внутри домена, а не в DWH. Это позволяет финтех-команде выпускать продукты независимо.

### Граница Платформы данных

Платформа данных — потребитель событий из всех доменов, но не хранит операционные данные. Её задача — аналитика. Разделение OLTP и OLAP нагрузок устраняет конкуренцию за ресурсы, из-за которой отчёты в текущей архитектуре строятся часами.

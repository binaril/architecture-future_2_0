## 3. Описание этапов и бизнес-обоснование

### Фаза 1: Аудит и проектирование (месяцы 1–2, июнь–июль 2026)

**Цель:** сформировать и согласовать техническое решение до начала активных изменений.

| Параметр                | Содержание                                                                                                                                                |
|-------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Задачи**              | Аудит SQL Server 2008 и оценка рисков безопасности; проектирование целевой облачной архитектуры; согласование доменных границ; выбор облачного провайдера |
| **Ожидаемый результат** | Согласованная архитектура, определённые домены, выбранный стек — M1                                                                                       |
| **Ответственные**       | Архитектурная команда, руководители направлений Клиники / Финтех / ИИ                                                                                     |
| **Ресурсы**             | 2–3 архитектора, юридическая экспертиза по 152-ФЗ                                                                                                         |

**Бизнес-обоснование:** без согласованного плана каждая команда начнёт двигаться в своём направлении. Фаза длится 2 месяца — это инвестиция, которая предотвращает месяцы переделок.

---

### Фаза 2: Фундамент платформы данных (месяцы 3–7, август–ноябрь 2026)

**Цель:** создать базу для быстрой аналитики и устранить регуляторный риск с медданными.

| Параметр                | Содержание                                                                                                                                                                      |
|-------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Задачи**              | Развёртывание Cloud-инфраструктуры; настройка Kafka и API Gateway; физическая изоляция медданных; создание Data Lake; первые ETL-пайплайны в Airflow; миграция DWH → ClickHouse |
| **Ожидаемый результат** | Медданные изолированы (M2); аналитический DWH в облаке (M3); данные текут через Kafka                                                                                           |
| **Ответственные**       | DevOps / Cloud-команда, команда данных (Data Engineering), CISO                                                                                                                 |
| **Ресурсы**             | 4–5 инженеров данных, 2 DevOps, облачный бюджет на инфраструктуру                                                                                                               |

**Бизнес-обоснование:**
- Изоляция медданных снимает юридический риск (штрафы до 6% выручки по 152-ФЗ) — это блокирующее условие для развития ИИ-сервисов.
- Миграция на ClickHouse сокращает время формирования отчётов с нескольких часов до 5–30 минут → руководство получает данные для принятия решений вовремя.

---

### Фаза 3: Запуск портала самообслуживания (месяцы 7–10, декабрь 2026 – март 2027)

**Цель:** реализовать ключевой бизнес-запрос — витрину данных для самостоятельной работы аналитиков.

| Параметр                | Содержание                                                                                                                                  |
|-------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|
| **Задачи**              | Развёртывание Apache Superset с ролевым доступом; ETL-пайплайны для всех доменов; запуск DataHub; онбординг и обучение первых пользователей |
| **Ожидаемый результат** | Портал самообслуживания доступен бизнесу; аналитики строят отчёты без IT-запросов                                                           |
| **Ответственные**       | Команда данных, Product Owner витрины, руководители доменов                                                                                 |
| **Ресурсы**             | 3 аналитика данных, 2 инженера данных, Product Owner                                                                                        |

**Бизнес-обоснование:** достигается ключевая промежуточная цель — «реализован портал самообслуживания». Снижение нагрузки на IT-отдел на 40–60% за счёт устранения ручных запросов на построение отчётов. DataHub обеспечивает доверие к данным — без каталога витрина не используется.

---

### Фаза 4: Независимость доменов (месяцы 10–14, март–июль 2027)

**Цель:** перевести каждый домен на независимый жизненный цикл, вывести устаревшие системы.

| Параметр                | Содержание                                                                                                                                                               |
|-------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Задачи**              | Запуск нового МИС (замена PowerBuilder); изоляция финтех-домена с переносом бизнес-логики; запуск AI Platform и MLflow; замена Camel ESB на Kafka; вывод SQL Server 2008 |
| **Ожидаемый результат** | SQL Server 2008 выведен (M5); все домены работают независимо (M6)                                                                                                        |
| **Ответственные**       | Команды Финтех, Клиники, ИИ — каждая отвечает за свой домен                                                                                                              |
| **Ресурсы**             | 3 команды по 4–6 разработчиков, тест-инженеры, архитектор для координации                                                                                                |

**Бизнес-обоснование:**
- Финтех-команда выпускает продукты (например, «кредит на лечение») без ожидания пересборки DWH → time-to-market сокращается с месяцев до недель.
- Вывод SQL Server 2008 устраняет критическую уязвимость безопасности и ежегодные расходы на поддержку устаревшей инфраструктуры.
- ИИ-команда деплоит новые модели диагностики независимо → ускорение вывода ИИ-продуктов на рынок.

---

### Фаза 5: Масштабирование на партнёров (месяцы 14–18, июль–сентябрь 2027)

**Цель:** подключить новые бизнес-направления без изменений в существующих доменах.

| Параметр                | Содержание                                                                                                                                            |
|-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Задачи**              | Интеграция фармацевтических партнёров через Kafka; интеграция производителя медоборудования; внедрение принципов Data Mesh; полный вывод PowerBuilder |
| **Ожидаемый результат** | Целевая архитектура полностью реализована (M7); новые партнёры подключены                                                                             |
| **Ответственные**       | Интеграционная команда, команды партнёров, Platform Engineering                                                                                       |
| **Ресурсы**             | 2 интеграционных инженера, партнёрские команды для адаптеров                                                                                          |

**Бизнес-обоснование:** подключение фарм. партнёров открывает новые источники выручки (e-commerce препаратов, аналитика по назначениям). Данные медоборудования обогащают ИИ-модели диагностики. Data Mesh закрепляет масштабируемую модель — следующий партнёр интегрируется за 2–4 недели, а не за месяцы.
